# ТЕХНІЧНЕ ЗАВДАННЯ: Етап 5 — Керування послугами (Live Sync), Розклад майстрів, Розширене відхилення заявок з причинами та Програма лояльності

## 1. Загальна інформація та мета етапу
- **Мета:**
  1. **Керування послугами (Admin Bot ➔ Mini App Live Sync):** можливість увімкнути/вимкнути послугу (`is_active`) в один клік, змінити ціну та додати нову послугу прямо з бота. Зміни миттєво відображаються у Telegram Mini App.
  2. **Керування розкладом майстрів:** статус активності майстра (`is_active`), можливість в один клік позначити день як вихідний або додати технічну перерву/блокування годин.
  3. **Розширене відхилення заявок з причинами:** при відхиленні заявки адмін може вибрати шаблонну причину (зайнято, лікарняний, тех. перерва) або ввести індивідуальну причину вручну. Клієнту надходить ввічливе персоналізоване повідомлення з кнопкою повернення до Mini App.
  4. **Клієнти студії та Програма лояльності:** облік візитів, автоматичні статуси лояльності (Постійний клієнт -5%, VIP -10%) та можливість надати персональну знижку.
  5. **Збереження текстового каталогу клієнта:** швидкий і зручний текстовий перегляд цін та майстрів у боті без обов'язкового запуску TMA.
- **GitHub Repository:** `https://github.com/RissAR/nails_bot.git` (гілка `main`)
- **Стек:** aiogram 3.x (FSM, Routers, Inline Keyboards), FastAPI, SQLAlchemy 2.0 (Async), React Mini App.

---

## 2. Суворі правила безпеки (Strict Security & Scope Discipline)
1. **Zero Hardcoded Secrets (КРИТИЧНО):** `BOT_TOKEN` та інші конфіденційні дані зчитуються **виключно з локального `.env`**. Заборонено записувати токени у файли коду або дефолтні значення класів `Settings`.
2. **Zero Scope Creep:** Модифікувати тільки хендлери адміна та клієнта, клавіатури, моделі (додавання полів лояльності), сервісні ендпоінти.
3. **Git Автоматизація:** Після завершення роботи виконати:
   `git add . && git commit -m "feat: implement service CRUD, schedule management, rejection reasons and loyalty program" && git push origin main`.

## 3. Деталі технічної реалізації

### 3.1. Керування послугами з Live Sync (`src/handlers/admin.py`, `src/keyboards/admin_kb.py`)
- У розділі `admin_services` (Список послуг):
  - Для кожної категорії виводити список послуг.
  - Під кожною послугою (або при натисканні на послугу) додавати кнопки:
    - `[ 🟢 Активна ]` / `[ 🔴 Вимкнена ]` (callback: `adm_toggle_srv:{id}`) ➔ перемикає `service.is_active`. Коли послуга вимкнена, вона автоматично ховається і в боті, і в Mini App (`GET /api/services`).
    - `[ ✏️ Змінити ціну ]` (callback: `adm_price_srv:{id}`) ➔ активує стан FSM `AdminServiceFSM.waiting_new_price`. Бот запитує нову вартість, валідує число (`> 0`) та оновлює ціну в БД. Нова ціна відразу показується в Mini App.
  - Внизу списку категорій додати кнопку:
    - `[ ➕ Додати нову послугу ]` ➔ покроковий FSM (вибір категорії ➔ назва ➔ тривалість у хвилинах ➔ ціна).

---

### 3.2. Керування майстрами та розкладом (`src/handlers/admin.py`)
- У розділі `admin_masters_schedule`:
  - Список майстринь (Олена, Вікторія) з кнопками:
    - `[ 🟢 Приймає ]` / `[ 🔴 Не приймає ]` (callback: `adm_toggle_mst:{id}`) ➔ перемикає `master.is_active`.
    - `[ 🛑 Встановити вихідний на завтра ]` (callback: `adm_dayoff_mst:{id}:tomorrow`) ➔ створює запис у розкладі/блокуваннях на завтра для цього майстра, знімаючи всі слоти в Mini App.
    - `[ ⏸ Додати перерву / блок годин ]` (callback: `adm_block_slot:{id}`) ➔ через FSM запитує дату та часовий діапазон (наприклад: `14:00-15:00`).

### 3.3. Активні заявки та сценарій відхилення з причинами
1. **Під карткою нової заявки та у списку активних заявок (`adm_rejc:{appointment_id}`):**
   - Замість миттєвого видалення бот відкриває меню вибору причини:
     ```text
     ❓ Оберіть причину відхилення заявки #{appointment_id} або напишіть свою:
     ```
   - Інлайн-кнопки:
     - `[ ⏳ Майстер зайнятий на цей час ]` (callback: `adm_rej_reason:{id}:busy`)
     - `[ 🤒 Майстер на лікарняному ]` (callback: `adm_rej_reason:{id}:sick`)
     - `[ ⚡️ Технічна перерва / Немає світла ]` (callback: `adm_rej_reason:{id}:tech`)
     - `[ ✍️ Вказати власну причину ]` (callback: `adm_rej_custom:{id}`)
     - `[ ◀️ Скасувати відхилення ]` (callback: `admin_pending_appointments`)

2. **Обробка шаблону або власної причини:**
   - Шаблонні тексти:
     - `busy`: *"На жаль, на цей час майстер вже зайнятий або веде прийом іншого клієнта."*
     - `sick`: *"На жаль, майстер раптово захворів(ла) та сьогодні не приймає."*
     - `tech`: *"У студії заплановано технічну перерву (відсутність електроенергії/регламентні роботи)."*
   - Якщо адмін обрав `adm_rej_custom`:
     - Бот активує стан FSM `AdminRejectFSM.waiting_custom_reason` і очікує повідомлення від адміна в чат.

3. **Сповіщення клієнту:**
   - Статус у БД змінюється на `rejected`, зберігається `cancellation_reason`.
   - Повідомлення в чаті адміна оновлюється: `❌ Заявку #{id} відхилено (Причина: {reason})`.
   - Клієнту надсилається повідомлення:
     ```html
     😔 <b>Ваш запис на {date} о {time} скасовано</b>

     <b>Причина:</b> {reason_text}

     Будь ласка, оберіть інший зручний час у нашому Mini App або зв'яжіться з адміністратором: @andriy_bot_dev
     ```
   - Під повідомленням прикріплюється кнопка:
     `[ 💅 Обрати інший час (Mini App) ]`.

### 3.4. Розділ «Клієнти студії» та Програма лояльності
1. **Розширення моделі `User` (`src/database/models/user.py`):**
   - Додати поля (якщо відсутні):
     - `completed_visits: Mapped[int] = mapped_column(Integer, default=0)`
     - `total_spent: Mapped[float] = mapped_column(Float, default=0.0)`
     - `discount_percent: Mapped[int] = mapped_column(Integer, default=0)`
   - Автоматичне оновлення: при зміні статусу запису на `confirmed` (або `completed`) збільшувати `completed_visits` та додавати суму до `total_spent`.

2. **Рівні лояльності (Розрахунок):**
   - 0–2 завершені візити ➔ `Новий клієнт (0%)`
   - 3–6 завершених візитів ➔ `Постійний клієнт (-5%)`
   - 7+ завершених візитів ➔ `VIP-клієнт (-10%)`
   - Якщо адмін вручну встановив `discount_percent > 0`, використовується більше значення.

3. **Інтерфейс адміна (`admin_clients_stats`):**
   - Кнопка `[ 👥 Список клієнтів ]` (посторінковий перегляд топ-клієнтів або останніх активних).
   - Відображення картки:
     ```text
     👤 Олена Ковальчук (@olena_k)
     📞 +380971234567
     💅 Візитів: 4 | Сума: 2 300 грн
     🏷 Рівень: Постійний клієнт (знижка 5%)
     ```
   - Кнопка `[ 🎁 Змінити персональну знижку ]` (встановлення фіксованого % через FSM).

4. **Відображення знижки в Mini App:**
   - У `GET /api/auth/me` повертати `discount_percent`.
   - Якщо `discount_percent > 0`, у формі бронювання Mini App показувати:
     `🏷 Ваша персональна знижка: -{discount_percent}%` та перераховану фінальну суму.

### 3.5. Збереження текстового каталогу для клієнта
- Перевірити та гарантувати, що в `src/handlers/client.py`:
  - Кнопка `💅 Послуги та ціни` виводить тільки активні послуги (`is_active == True`), коректні категорії, оновлені ціни та тривалості.
  - Кнопка `👩‍🎨 Наші майстри` виводить тільки активних майстринь з їхніми актуальними графіками та спеціалізацією.
  - Біля кожної позиції доступні швидкі кнопки переходу в Mini App.

## 4. Критерії приймання та валідація (Acceptance Criteria)
1. Адмін може в 1 клік вимкнути послугу, і вона миттєво зникає з Mini App та текстового каталогу.
2. Адмін може змінити ціну послуги через бота, і оновлена ціна відображається в Mini App без перезапуску бекенду.
3. При відхиленні заявки адміну пропонуються 3 шаблонні причини та введення власної; клієнт отримує точну причину з кнопкою повторного запису.
4. У розділі клієнтів відображаються рівні лояльності, знижки зберігаються в базі та враховуються при замовленні.
5. Текстовий каталог клієнта в боті залишається повністю функціональним і швидким.
6. Фронтенд Mini App збирається без помилок (`npm run build`).
7. Усі токени завантажуються виключно з `.env`.
8. Зміни закомічені та відправлені на GitHub:
   ```bash
   git add .
   git commit -m "feat: implement service CRUD, schedule management, rejection reasons and loyalty program"
   git push origin main
   ```
