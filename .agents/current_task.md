# ТЕХНІЧНЕ ЗАВДАННЯ: Етап 4 — Жорсткий RBAC у Mini App, Валідація (+380, Кирилиця, Anti-XSS) та Гібридні сповіщення про записи

## 1. Загальна інформація та мета етапу
- **Мета:**
  1. **Жорсткий поділ ролей у Mini App:** повністю видалити ручний перемикач клієнт/адмін. Адмін бачить **виключно** `AdminDashboard`, клієнт — **виключно** форму бронювання.
  2. **Сувора валідація та Anti-XSS:** 
     - Номер телефону: виключно український формат `+380` + 9 цифр (з маскою та обмеженням довжини).
     - Ім'я: виключно кирилиця (українські літери, дефіс, апостроф), без цифр, латиниці та спецсимволів.
     - Захист від XSS: екранування всіх вхідних рядків перед збереженням та надсиланням у Telegram.
  3. **Гібридна система обробки заявок:**
     - При створенні запису надсилати детальне сповіщення в бот адміністратора (`8607080614`) з інлайн-кнопками `[ ✅ Підтвердити ]` та `[ ❌ Відхилити ]`.
     - Додати можливість підтвердження/відхилення як через інлайн-кнопки в боті, так і через Mini App адміна.
     - При зміні статусу автоматично надсилати сповіщення клієнту в Telegram.
- **GitHub Repository:** `https://github.com/RissAR/nails_bot.git` (гілка `main`)
- **Стек:** React, Vite, TypeScript, Tailwind CSS, FastAPI, aiogram 3.x, SQLAlchemy 2.0.

## 2. Суворі правила безпеки (Strict Security & Scope Discipline)
1. **Zero Hardcoded Secrets (КРИТИЧНО):** `BOT_TOKEN` та інші конфіденційні дані зчитуються **виключно з локального `.env`**. Заборонено записувати токени у файли коду або дефолтні значення.
2. **Zero Scope Creep:** Модифікувати тільки фронтенд Mini App, ендпоінти бронювання, валідатори та хендлери сповіщень. Не чіпати сторонні модулі.
3. **Git Автоматизація:** Після завершення роботи виконати:
   `git add . && git commit -m "feat: enforce strict RBAC, phone/XSS validation, and hybrid booking notifications" && git push origin main`.

## 3. Деталі технічної реалізації

### 3.1. Жорсткий поділ ролей у Mini App (`frontend/src/App.tsx`)
- **Видалити верхній таб-перемикач** `[ 💅 Клієнтська аппка | ⚙️ Панель адміна ]`.
- При завантаженні додатку запитувати `GET /api/auth/me` (з передачею `initData` або `tg_id`):
  - Якщо `user.role === "admin"` (або `telegram_id === 8607080614`) ➔ рендерити **виключно** `<AdminDashboard />`.
  - Якщо `user.role === "client"` ➔ рендерити **виключно** `<ClientBookingFlow />`.
- Клієнт не має доступу до адмінки, адмін не бачить клієнтського флоу при вході зі свого адмінського акаунта.

### 3.2. Валідація телефону, імені та Anti-XSS (Frontend + Backend)

#### Frontend (`frontend/src/components/BookingModal.tsx` або форма контактів):
1. **Поле «Номер телефону»:**
   - Фіксований префікс: `+380 `. Користувач не може його стерти.
   - Дозволений ввід: **тільки цифри** `0-9`.
   - Обмеження: рівно 9 цифр після `+380` (наприклад, `+380 97 123 45 67`).
   - Загальна довжина строго обмежена.
   - Кнопка підтвердження запису неактивна, якщо не введено всі 9 цифр.
2. **Поле «Ім'я»:**
   - Дозволені символи: виключно українська кирилиця `[А-Яа-яІіЇїЄєҐґ'\s\-]`.
   - Будь-яке введення латиниці, цифр або спецсимволів (`<`, `>`, `/`, `@`, `$`, `&` тощо) блокується миттєво в `onChange`.
   - Обмеження довжини: від 2 до 40 символів.

#### Backend (`src/api/routes/bookings.py`):
1. **Pydantic-валідація `BookingCreateRequest`:**
   - `client_phone`: регулярний вираз `^\+380\d{9}$`. При невідповідності повертати HTTP 422 з чітким описом: *"Номер телефону має бути у форматі +380XXXXXXXXX (9 цифр після коду країни)"*.
   - `client_name`: регулярний вираз `^[А-Яа-яІіЇїЄєҐґ'\s\-]{2,40}$`. При невідповідності повертати HTTP 422: *"Ім'я має містити виключно українські літери (від 2 до 40 символів)"*.
2. **Anti-XSS санітизація:**
   - Усі текстові поля (`client_name`, `notes`) обробляти через `html.escape()` перед збереженням у БД та перед формуванням повідомлень Telegram (щоб уникнути HTML-ін'єкцій у Bot API та XSS у Mini App).

### 3.3. Сповіщення адміна про новий запис (Telegram Bot)

У `src/api/routes/bookings.py` після успішного створення `Appointment`:
- Отримати екземпляр `Bot` (з `main.py` або через синглтон/хелпер).
- Сформувати картку повідомлення для кожного адміна з `settings.ADMIN_IDS`:
  ```html
  🔔 <b>НОВА ЗАЯВКА НА ЗАПИС #{appointment_id}</b>
  ━━━━━━━━━━━━━━━━━━━━━━
  👤 <b>Клієнт:</b> {client_name}
  📞 <b>Телефон:</b> {client_phone}
  💅 <b>Послуга:</b> {service_name} ({duration_minutes} хв, {price} грн)
  👩‍🎨 <b>Майстер:</b> {master_name}
  📅 <b>Дата:</b> {booking_date}
  ⏰ <b>Час:</b> {start_time} – {end_time}
  💬 <b>Коментар:</b> {notes or "—"}
  ```
- Додати інлайн-клавіатуру:
  ```python
  InlineKeyboardMarkup(inline_keyboard=[
      [
          InlineKeyboardButton(text="✅ Підтвердити", callback_data=f"adm_appr:{appointment_id}"),
          InlineKeyboardButton(text="❌ Відхилити", callback_data=f"adm_rejc:{appointment_id}"),
      ],
      [
          InlineKeyboardButton(text="💬 Написати клієнту", url=f"tg://user?id={client_tg_id}"),
      ] if client_tg_id > 0 else []
  ])
  ```

### 3.4. Обробка дій адміна в боті (`src/handlers/admin.py`)

1. **Callback `adm_appr:{appointment_id}` (Підтвердження):**
   - Змінити статус запису в БД на `"confirmed"`.
   - Оновити повідомлення адміна в чаті:
     додати рядок `\n\n✅ <b>ЗАЯВКУ ПІДТВЕРДЖЕНО</b>`.
   - Надіслати клієнту в Telegram (якщо `client.telegram_id > 0`):
     ```html
     ✨ <b>Ваш запис підтверджено!</b>

     💅 <b>Послуга:</b> {service_name}
     👩‍🎨 <b>Майстер:</b> {master_name}
     📅 <b>Дата:</b> {booking_date} о {start_time}
     📍 <b>Локація:</b> м. Івано-Франківськ, вул. Січових Стрільців

     Чекаємо на вас у Sense Nail Studio! Якщо ваші плани зміняться, будь ласка, попередьте нас завчасно.
     ```
2. **Callback `adm_rejc:{appointment_id}` (Відхилення):**
   - Змінити статус запису в БД на `"rejected"`.
   - Оновити повідомлення адміна в чаті:
     додати рядок `\n\n❌ <b>ЗАЯВКУ ВІДХИЛЕНО</b>`.
   - Надіслати клієнту в Telegram:
     ```html
     😔 <b>На жаль, ваш запис на {booking_date} о {start_time} відхилено адміністратором.</b>

     Можливо, на цей час заплановано технічну перерву або майстер зайнятий.
     Будь ласка, оберіть інший зручний час у Mini App або зв'яжіться з нами: @andriy_bot_dev.
     ```

### 3.5. Клікабельність та дії в Mini App Адміна (`AdminDashboard.tsx`)

1. **Ендпоінти в `src/api/routes/bookings.py`:**
   - `PATCH /api/admin/bookings/{id}/confirm` ➔ оновлює статус на `confirmed` і надсилає повідомлення клієнту в Telegram.
   - `PATCH /api/admin/bookings/{id}/reject` ➔ оновлює статус на `rejected` і надсилає повідомлення клієнту в Telegram.
2. **Фронтенд `AdminDashboard.tsx`:**
   - У списку заявок зробити картки інтерактивними.
   - Для заявок у статусі `pending` додати реальні кнопки:
     `[ ✅ Підтвердити ]` та `[ ❌ Відхилити ]`.
   - При натисканні викликається відповідний `PATCH` ендпоінт, статус миттєво оновлюється в інтерфейсі без перезавантаження сторінки.

## 4. Критерії приймання та валідація (Acceptance Criteria)
1. У Mini App відсутній таб-перемикач: адмін бачить тільки адмінку, клієнт — тільки форму запису.
2. Номер телефону не приймає символів, окрім цифр, і строго починається з `+380` (довжина рівно 12 цифр).
3. Ім'я не приймає латиниці чи спецсимволів (тільки українська кирилиця).
4. Запит із некоректними даними повертає 422 від бекенду.
5. При оформленні запису в чат адміна `8607080614` приходить повідомлення з кнопками `[ ✅ Підтвердити ]` та `[ ❌ Відхилити ]`.
6. Натискання `[ ✅ Підтвердити ]` (як у боті, так і в TMA) змінює статус на `confirmed` та надсилає клієнту красиве сповіщення про підтвердження.
7. `npm run build` у `frontend/` збирається без помилок (код 0).
8. Зміни закомічені та відправлені на GitHub:
   ```bash
   git add .
   git commit -m "feat: enforce strict RBAC, phone/XSS validation, and hybrid booking notifications"
   git push origin main
   ```
